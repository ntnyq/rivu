# 故障排查

如果 Rivu 能正常打开，但传输出现问题，请先查看任务错误提示与 **连接** 页，修复原因后再重试。

## macOS 阻止打开 Rivu

当前 macOS 下载包尚未使用 Apple Developer ID 签名，也未经过 Apple 公证。如果 macOS 提示无法验证开发者或无法检查应用是否包含恶意软件，请先确认下载来源，再按[被 macOS 拦截时打开 Rivu](getting-started.md#被-macos-拦截时打开-rivu)操作。指南包含 macOS 13 及以上版本的**仍要打开**步骤，以及 macOS 12 对应的设置入口。

如果验证弹窗只提供**移到废纸篓**和**完成**，请点击**完成**保留 Rivu。然后进入 **系统设置 → 隐私与安全性**，向下滚动到**安全性**，在 Rivu 被阻止的提示旁点击**仍要打开**，按要求验证身份后，在确认框中点击**打开**。

## 磁力链接被拒绝或无法解析

检查链接是否包含明确的 Tracker 或对等节点地址。在元数据确认种子是否私有之前，Rivu 只使用这些地址。只有信息哈希、没有 Tracker 或节点的链接无法用于当前预览流程。

预览在 45 秒后超时，可检查网络与链接来源后重试。取消预览或关闭添加窗口，不会向目标目录写入下载文件内容。

## 任务一直等待节点

等待不一定表示错误。在 **连接** 页查看节点数量与各 Tracker 的通告结果，先处理网络或 Tracker 问题再重试；不可用的资源群无法提供缺失分片。

诊断信息每五秒刷新一次。Tracker 行会隐藏凭据，分享诊断信息前仍请检查内容。

Windows 上请确认代理客户端使用的是系统代理还是 TUN。HTTP/HTTPS Tracker 和 TCP 节点可以使用系统代理，UDP Tracker 与 DHT 则需要可用的系统路由或支持 UDP 的 TUN，详见[系统代理与 TUN](settings.md#系统代理与-tun)。任务连续 90 秒没有进展会让出下载名额，等待一分钟后重试，因此「等待节点」可能暂时变成「等待队列」。

## 保存位置已有文件

新下载请选择没有冲突文件的位置。需要复用已有数据时，在添加窗口启用 **接管并校验已有文件**。任务运行时会校验这些文件并修复缺失分片。

移除任务会保留接管的文件。监视文件夹自动导入时不会自动接管数据。

## 下载目录发生变化

磁盘断开或文件已被搬移时：

1. 重新连接磁盘，或将数据放到可访问的位置。
2. 选择任务，在详情面板点击 **修改位置…**。
3. 选择包含种子顶层名称的目录并确认。
4. 准备就绪后重试或恢复任务。

修改位置不会从旧目录搬移文件。新位置的数据会在任务运行时校验，移除任务时保留；手动暂停的任务仍会保持暂停。

## 恢复批次后有任务没有继续

**恢复暂停批次**只恢复最近一次批量暂停，之前已单独暂停的任务会保持暂停。请使用任务自身的操作恢复它；定时限速也不会恢复已暂停任务。

## 移到废纸篓失败

检查目标磁盘是否在线、是否可写，再根据错误提示处理。Rivu 会记录已完成的移除步骤，不会将失败的废纸篓操作改为永久删除。接管的已有文件无法通过任务移到废纸篓。

## 备份或修复会话

应用数据默认位置因系统而异：macOS 为 `~/Library/Application Support/Rivu`，Windows 为 `%AppData%\Rivu`，Linux 为 `$XDG_CONFIG_HOME/Rivu`（未设置时为 `~/.config/Rivu`）。详见[数据保存位置](settings.md#数据保存位置)。

其中包含 `settings.json`、`session.json`、不可变种子元数据和文件归属日志。文件夹监视账本位于配置文件旁边；下载内容独立保存在各任务的目标目录。

备份前先退出 Rivu，再复制应用数据目录，以及存放在其他位置的配置文件。需要继续原有传输时，也要保留下载文件。

文件损坏或较新版本的结构导致加载受阻时，请先备份受影响文件再修复。完成后选择 **文件 → 修复后重新加载会话与设置**。不要仅为消除错误就用空文件替换会话。

恢复任务会重新校验实际数据。上传总量与累计做种时长每 15 秒保存一次，强制终止可能丢失最近一个统计周期。会话结构版本 1 会迁移至版本 2，只支持版本 1 的旧应用无法打开迁移后的会话。

## 更新检查不可用

请使用安装在可写位置的发行构建。开发模式、未配置更新源的旧版本和只读安装无法自行更新。macOS 请将 Rivu 从 DMG 复制到“应用程序”；Linux DEB 安装请通过包管理器更新。未配置更新源的旧版本需要先手动安装一次支持更新的发行版。显示不可用不代表已经是最新版，详见[更新设置](settings.md#更新)。

## Windows 检查更新提示 EOF 或超时

`EOF` 或 `unexpected EOF` 表示连接或响应提前结束，不代表已经是最新版，也不代表更新签名校验失败。Windows 发行构建使用 `update-windows-amd64.json`。

Rivu 对中断或超时的更新检查最多重试两次。Windows 优先使用已配置的代理环境变量，否则读取当前 Windows 系统代理，包括自动配置脚本（PAC），并遵守代理例外。启用可用的系统代理后即可再次检查，无需必须开启 TUN 模式。浏览器能访问 GitHub，不代表 Rivu 的代理路径也可用。

若仍失败，请确认配置的代理正在运行，且允许访问 `github.com` 和重定向后的发行下载域名。从终端启动 Rivu 时，还应检查 `HTTP_PROXY`、`HTTPS_PROXY` 与 `NO_PROXY`，因为它们优先于系统代理选择。即使已经安装最新版，也可以再次检查：Rivu 会先获取清单，再比较版本。若问题持续，请反馈最后一次的完整错误，并在分享前去除代理凭据。
